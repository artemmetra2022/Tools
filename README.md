# ClearItems — мод для NeoForge 1.21.1

Добавляет команду `/clear1`, которая удаляет **все** предметы, лежащие
на земле, во всех измерениях мира (эквивалент `/kill @e[type=item]`),
а также её вариант `/clear1 radius <N>` — очистка только вокруг себя.

Также добавляет два предмета:
- **Жезл Очистки** (Wand of Clearing) — по правому клику по любому
  блоку удаляет все предметы, лежащие на земле, в настраиваемом
  радиусе (по умолчанию 50 блоков).
- **Жезл Заморозки** (Freeze Wand) — по правому клику разбирает
  ближайшую движущуюся конструкцию (contraption) мода **Create**
  обратно в настоящие блоки, полностью останавливая её движение.
  **Требует установленный мод Create 6.0.x для NeoForge 1.21.1.**

Существует **whitelist** предметов, которые мод никогда не удалит
с земли — настраивается в конфиге (см. ниже).

## Использование

### Команда

В игровом чате (или консоли сервера) введите:

```
/clear1
```

— очистить **все** загруженные измерения сервера, или:

```
/clear1 radius 32
```

— удалить предметы только в **сфере** радиусом N блоков вокруг
вызвавшего (в его текущем измерении). N — целое число от 1.

Команда доступна игрокам с правами оператора (уровень permission 2 —
как у большинства ванильных игровых команд, `/gamemode`, `/give` и т.д.).
При желании поменять уровень доступа — см. `ClearItemsCommand.java`,
строка `.requires(source -> source.hasPermission(2))`.

### Команда помощи

```
/clearitemshelp
```

Выводит в чат краткую справку по обоим жезлам и командам мода.
Доступна всем игрокам без ограничений по правам.

### Приветствие при входе в мир

При каждом входе игрока в мир (логине на сервер, не при респавне)
мод один раз показывает в чате краткое описание своих возможностей
и подсказку про `/clearitemshelp` — логика в
`ClearItemsWelcomeHandler.java`.

### Whitelist — предметы, которые нельзя удалять

`/clear1` (в обоих вариантах) и Жезл Очистки **никогда** не удаляют
предметы из whitelist. Whitelist настраивается в серверном конфиге:

```
<папка_мира>/serverconfig/clearitems-server.toml
```

Файл создаётся автоматически при первом запуске мира с модом.
Содержимое по умолчанию:

```toml
[items]
    #Items that /clear1 and the Wand of Clearing never remove from the ground.
    #Format: "modid:item_id", one per line. Example: "minecraft:nether_star"
    whitelist = ["minecraft:nether_star"]
```

Добавляйте ID предметов в формате `"modid:item_id"` — по одному на
строку (в TOML список пишется в квадратных скобках, элементы через
запятую). Пример защиты сразу нескольких предметов:

```toml
whitelist = ["minecraft:nether_star", "minecraft:dragon_egg", "create:shadow_steel"]
```

Изменения файла подхватываются при следующем запуске мира/сервера
(server-конфиг читается при загрузке мира, поэтому после правки
конфига нужен рестарт).

Если при очистке часть предметов была пропущена по whitelist, мод
напишет об этом в сообщении: «Удалено предметов с земли: 42
(пропущено по whitelist: 3)».

### Жезл Очистки (предмет)

Получить предмет можно командой:

```
/give @s clearitems:wand_of_clearing
```

либо найти его во вкладке творческого инвентаря **"Инструменты и утилиты"**.

При правом клике по любому блоку (земля, камень, трава и т.д.) жезл
удалит все `ItemEntity` (выброшенные/лежащие предметы) в радиусе от
точки клика, проиграет звук и напишет игроку, сколько предметов
было удалено. Радиус по умолчанию — **50 блоков**; переключается
циклически по **Shift+ПКМ в воздухе**: `8 → 16 → 32 → 50 → 100`,
значение сохраняется в самом предмете (data components). Логика —
`WandOfClearingItem.java`, константы `RADIUS_STEPS`/`DEFAULT_RADIUS`.

Жезл не расходуется при использовании (не ломается, не пропадает).

### Жезл Заморозки (требует установленный мод Create)

**Важно:** этот предмет работает только если в игре установлен мод
**Create** версии 6.0.x для NeoForge 1.21.1. Мод объявлен как
обязательная (`required`) зависимость в `neoforge.mods.toml` — без
Create ClearItems откажется загружаться вообще (проверьте, что у вас
всё-таки стоит Create, если игра не запускается).

Получить предмет:

```
/give @s clearitems:freeze_wand
```

При правом клике по любому блоку жезл ищет ближайшую движущуюся
конструкцию Create (contraption — механический подшипник с
автоматическим сборщиком пшеницы, бур, поршневая конструкция, лифт
и т.д.) в радиусе поиска (по умолчанию **32 блока**, переключается
циклически по **Shift+ПКМ в воздухе**: `8 → 16 → 32 → 64`) и
принудительно "сажает" её — превращает контрапшн обратно в настоящие
статичные блоки в мире, полностью останавливая всякое движение.
Работает в два клика: первый — подсвечивает ближайшую конструкцию
(эффект Glowing) и пишет количество блоков, повторный в течение 5
секунд — разбирает. Это тот же самый процесс,
который Create выполняет сам при штатной остановке конструкции
(например когда механический подшипник просто выключают) — здесь он
вызывается вручную по клику через публичный метод `disassemble()`
класса `AbstractContraptionEntity` (общий базовый класс всех
контрапшнов Create).

Радиус поиска настраивается в файле `FreezeWandItem.java`,
константы `RADIUS_STEPS`/`DEFAULT_RADIUS`.

#### Если сборка не проходит из-за зависимости Create

Сейчас в проекте зашита версия **Create 6.0.8** для NeoForge 1.21.1
(File ID `7178775`, файл `create-1.21.1-6.0.8.jar`, опубликован
2 ноября 2025). Мод Create периодически обновляется, и файл на
CurseForge может смениться. Если GitHub Actions выдаёт ошибку
скачивания зависимости `curse.maven:create-328085:...`:

1. Откройте https://www.curseforge.com/minecraft/mc-mods/create/files
   и найдите актуальный релиз для **NeoForge 1.21.1**.
2. Скопируйте его **File ID** (виден в URL страницы файла или через
   кнопку "Copy" рядом с "Install via app").
3. Обновите значение `create_curseforge_file_id` в `gradle.properties`.

Если проблема не в версии, а сам CurseMaven недоступен, в
`build.gradle` уже подключён резервный репозиторий Modrinth Maven —
можно заменить строку зависимости на:
```gradle
implementation "maven.modrinth:LNytGWDc:<version-id-с-modrinth>"
```
(конкретный `<version-id>` берётся со страницы версии Create на
modrinth.com/mod/create/versions).

## Как собрать мод

1. Установите **JDK 21** (обязательно, NeoForge 1.21.1 требует Java 21).
2. Убедитесь, что есть доступ в интернет (Gradle скачает NeoForge
   и зависимости при первой сборке).
3. В корне проекта выполните:

   ```bash
   # Linux / macOS
   ./gradlew build

   # Windows
   gradlew.bat build
   ```

   Первая сборка может занять продолжительное время — Gradle скачивает
   Minecraft, mappings и NeoForge userdev окружение.

4. Готовый файл мода появится в:

   ```
   build/libs/clearitems-1.0.0.jar
   ```

5. Скопируйте этот `.jar` в папку `mods` вашего клиента или сервера
   с установленным **NeoForge 1.21.1** (использовалась версия
   NeoForge `21.1.172` — при необходимости поправьте `neo_version`
   в `gradle.properties` на актуальную для вашей сборки NeoForge).

## Тестовый запуск без полной сборки jar

Можно сразу запустить тестовый клиент или сервер через Gradle:

```bash
./gradlew runClient
# или
./gradlew runServer
```

## Автосборка на GitHub (GitHub Actions)

В проекте уже настроен workflow `.github/workflows/build.yml`.

**Как это работает:**
1. Загрузите весь проект (содержимое этой папки) в свой репозиторий на GitHub.
2. При каждом `git push` (в любую ветку) GitHub автоматически:
   - поднимет JDK 21,
   - установит Gradle,
   - соберёт мод командой `gradle --no-daemon build`,
   - выложит готовый `.jar` в **Artifacts**.
3. Чтобы скачать `.jar`:
   - откройте вкладку **Actions** в репозитории на GitHub,
   - выберите последний запуск workflow "Build" (зелёная галочка = успех),
   - внизу страницы будет раздел **Artifacts** → `clearitems-<hash коммита>`
     (zip, внутри — `clearitems-1.0.0.jar`).

Артефакты в GitHub Actions хранятся ограниченное время (обычно 90 дней
по умолчанию для бесплатных репозиториев) — если нужно хранить jar
дольше, дайте знать, добавлю автоматическое создание GitHub Release.

### Про gradle-wrapper.jar

Обычный шаблон Gradle-проекта содержит бинарный файл
`gradle/wrapper/gradle-wrapper.jar`. Он не включён в этот архив
(бинарники неудобно передавать вручную), но это не проблема:
workflow сам проверяет его наличие и при отсутствии генерирует через
официальный `gradle/actions/setup-gradle`. Если вы хотите собирать
мод **локально**, самый простой способ — один раз выполнить (при
наличии установленного Gradle 8.13+):

```bash
gradle wrapper --gradle-version 8.13
```

Это создаст недостающий `gradle-wrapper.jar`, после чего `./gradlew build`
будет работать и локально без дополнительной установки Gradle.
